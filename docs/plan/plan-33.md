# 每层固定数量的 API 共同题目抽样

1. 修改 `scripts/sample_shared_stratified_ids.py`：移除总量导向的 `--sample-size` 与 18 层配额分配；新增必填正整数参数 `--per-stratum-count <数量>`，表示每个“学科 × 难度”分层希望抽取的数量。

2. 保持可重复的 `--input-json <路径>`、精确 `sample_id` 交集、共同记录元数据一致性校验、三难度六学科分层、`--seed` 和仅输出 `sample_id` 列表的行为不变。

3. 对每个分层分别抽取 `min(--per-stratum-count, 该层可用共同样本数)` 条：
   - 可用数不少于请求数时，按请求数随机抽取；
   - 可用数少于请求数时，抽取该层全部可用样本；
   - 容量不足不再报错、不再中止，脚本仍正常写出全部已抽取的 `sample_id`。

4. 使用固定的学科、难度顺序输出；每层内按 `--seed` 决定抽样顺序。总输出数量不再预先固定，等于所有分层实际抽样数之和。

5. 屏幕逐层报告“可用数 / 请求数 / 实际抽取数”，并对不足的分层标记“已取上限”；最后输出请求的每层数量、实际总抽样数和输出路径。

6. 输入 JSON 非法、输入数少于两个、`sample_id` 重复、共同 `sample_id` 的学科/难度不一致、输出覆盖输入等数据完整性问题仍保留错误退出；仅容量不足改为正常完成。

7. 验收：对 GPT 与 GLM 的 API 原始数据运行。以每层 22 条为例，`physics/medium_high` 只有 15 条时，输出保留这 15 条并在摘要标记，而非退出；其余容量充足分层各输出 22 条。
